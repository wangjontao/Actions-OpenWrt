# FastACL V2.6.0

本次重大更新修复附加 WiFi 沿用参考无线 MAC、不同路由器出现相同 BSSID 的问题。
这类冲突可导致苹果及安卓手机连接一直转圈、WPA 握手失败，尚未进入 DHCP 阶段。

## 修复

- 每次 MTWiFi 生成配置时，按分区名称查找 Factory，校验 EEPROM 类型并读取本机真实无线 MAC。
- 将本机硬件身份写入无线基准配置，由驱动分配各 AP 的 BSSID，不再沿用参考配置。
- 移除上一版错误的独立 per-VAP 自动地址写入；迁移已识别的参考地址和旧自动生成地址。
- 新建附加 WiFi 前检查 Factory 数据；未知布局或无效地址会明确报错，不回退到共享参考 MAC。
- 包版本、默认配置、状态接口及页面标题统一为 V2.6.0；内部 fastacl252 配置与包名保留，兼容已有数据。
- DNS 菜单隐藏重复的“DNS 跟随代理出口（Cloudflare DoH）”，旧配置仍能解析；新配置默认 Cloudflare。

## 已验证

MT7981 / 中移 RAX3000M NAND：实际 12 个 AP BSSID 无重复、无参考地址；
双频临时 AP 新建、删除重建通过；用户实测手机连接、获取 IP、上网正常。

## 边界

- MT7986 源码同步本修复，但未完成实体机验证，不能宣称全型号实测通过。
- 专有 MTWiFi DBDC 可由主无线 MAC 统一派生双频地址；5G 实际 BSSID 不一定等于 Factory 中的 5G 基准原值。
- 增删 AP 可能触发 BSSID 重排；无线重载会短暂影响已连接客户端。
- 随机/自定义单个 WiFi MAC 尚未实现，不包含在本次更新中。
- 保留原有 BBR、解除并发限制、DNS、节点和设备绑定功能；无需重新初始化配置。

本版本使用独立源码分支和独立构建队列。
